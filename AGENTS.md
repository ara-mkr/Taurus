## Design and implementation

Follow `docs/11-design-rules.md`: system typeface, one ink, one signal red, rules instead of cards, no icons, badges, gradients or all-caps labels, nothing under 13 px. The horns mark has not been trademark-cleared.

Implement one assigned slice. Avoid new dependencies unless justified. Keep state and adapter boundaries small. Do not copy competitor assets or code without recording licensing/provenance. Do not execute scripts from unreviewed remote skills or repos.

## Skills and verification

Use the relevant Taurus skill: taurus-ui for building, taurus-ui-audit for independent review, taurus-phase-gate for scope/gates, taurus-action-safety for action design review. Read the actual SKILL.md when invoking; do not claim invocation from metadata alone.

Render the UI, inspect screenshots and keyboard behavior, run applicable tests, and report evidence. A passing build is not a visual audit. An audit is read-only unless editing was requested. Never invent passing tests or screenshot results.

Return objective, files changed, actual checks/results, screenshots, limitations and the next eligible task. Do not commit, push, publish, purchase, or change cloud/account settings unless explicitly authorized. Keep secrets and private data out of fixtures, logs and screenshots.
