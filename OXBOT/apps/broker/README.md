# Taurus sign-in service

Lets anyone click "Sign in with Google" (or Microsoft, Slack, GitHub, Notion, Linear, Spotify and the rest in `apps/server/src/providers.ts`) in their own Taurus and land on that company's own sign-in page, without registering developer apps.

What it does, and nothing more:

1. `GET /start`: checks the request (known provider, read-only scopes, return address on the user's own computer) and sends the browser to the provider with Taurus's client ID.
2. `GET /callback`: swaps the code for tokens using Taurus's client secret, encrypts them to a one-time key generated by the user's Mac (ECDH P-256 + AES-GCM), and redirects back to `http://localhost:…/api/oauth/handoff`.
3. `POST /refresh`: refreshes an access token, because that also needs the client secret.
4. `GET /providers`: which providers have keys, so Taurus knows where to show one-click sign-in.

It has no database and keeps no logs of tokens. Its OAuth state is an encrypted, 10-minute blob. Mail, calendars and health data never pass through it: each Taurus talks to the providers directly with its own tokens.

Live: https://oxbot-signin.oxbot-signin.workers.dev (Cloudflare Workers free plan, account akhil.ramudhan@gmail.com). Taurus uses it by default.

## Add a provider

Register Taurus's app with the provider, using `https://oxbot-signin.oxbot-signin.workers.dev/callback` as its redirect URL, then from `apps/broker` run `npx wrangler@4 secret put <PROVIDER>_CLIENT_ID` and `npx wrangler@4 secret put <PROVIDER>_CLIENT_SECRET` and paste each value when asked. Every Taurus picks it up within 10 minutes.

## Deploy on Cloudflare (free tier is enough)

```sh
cd apps/broker
npx wrangler@4 login
npx wrangler@4 secret put STATE_SECRET        # 32+ random characters: openssl rand -base64 48
npx wrangler@4 secret put WHOOP_CLIENT_ID      # repeat for each provider you have an app for
npx wrangler@4 secret put WHOOP_CLIENT_SECRET
npx wrangler@4 deploy
```

Then set `BROKER_URL` in `wrangler.toml` to the URL it prints, deploy again, and register `<BROKER_URL>/callback` as the redirect URL in each provider's developer app. In each user's Taurus, set `TAURUS_BROKER_URL=<BROKER_URL>`.

Any Node host works too: `PORT=8790 STATE_SECRET=… BROKER_URL=https://… node src/node.ts`.

## Provider apps to register (once, by the Taurus owner)

| Provider | Where | Notes |
|---|---|---|
| WHOOP | developer-dashboard.whoop.com | Needs a WHOOP account to register. |
| Google | console.cloud.google.com | Reuse project `oxbot-513223`. Over 100 users needs Google verification; Gmail read access also needs a yearly security assessment. |
| Microsoft | entra.microsoft.com | Multi-tenant + personal accounts. Publisher verification recommended. |
| Strava | strava.com/settings/api | New apps start limited to 1 athlete; request a capacity increase. |
| Oura | cloud.ouraring.com/oauth/applications | |
| Slack | api.slack.com/apps | User token scope `search:read` only. Turn on public distribution so other workspaces can sign in. |
| GitHub | github.com/settings/developers (OAuth app) | Taurus asks only for `notifications read:user`: review requests come from notifications, never code. |
| Notion | notion.so/profile/integrations (public integration) | No scopes: Notion's own screen asks which pages to share. Needs a privacy policy and terms URL. |
| Linear | linear.app/settings/api (OAuth application) | Scope `read`. |
| Spotify, Zoom, Todoist, Asana, Atlassian, monday.com, Dropbox, Box, Xero, Withings | each one's developer console | Same redirect URL; scopes are listed in `readScopes`. Spotify's development mode allows 25 allow-listed users. |
